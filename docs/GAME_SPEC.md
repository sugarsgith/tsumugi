# ゲーム仕様 — 保健室のつむぎ v2

この文書は `index.html` を読んだ仕様です。プレイヤーから見える挙動を変えたら、コードと一緒に更新してください。テスト版 `test/index.html` は、末尾の「テスト版だけにあるもの」以外、同じゲームです。

実装は HTML 1 枚の中の CSS と JavaScript です。サーバもセーブもありません。ページを読み込んだ瞬間に、下の「初期化」が一度走ります。

## 概念と導入

保健室の端末で、AI 相談員のつむぎが、先生とともに覚えている言葉を聞き直す小品です。文書タイトルは「保健室のつむぎ v2 — 拡張するタイムライン」。画面の見出しは「保健室のつむぎ」。その上の小さな肩書きは「AI相談員 つむぎ · Prototype 02」。

導入の一文は次のとおりです。

> 昼休みと放課後、保健室の端末でそっと話を聞く。証言の中の言葉が、まだ見ぬ続きに繋がっている。

プレイヤーがやることは、手札の証言を読み、誰が・いつの発言かを判断して、表の正しいマスへ置くことです。カードには話者名も時刻も書いてありません。正しく置くと、既読スルーのすれ違いが一つの流れとして読めます。基本の表が埋まると「わかったこと」と、放課後の一言を差し替える分岐が出ます。先生の証言に紛れている「莉子」をタップすると、夜の時間と莉子本人の証言が開きます。

つむぎ自身は表の列にはいません。語り手であり、手札のラベル「つむぎと先生が覚えている言葉」の主です。

## 登場人物

| 名前 | 役割 | 表のどこにいるか |
| --- | --- | --- |
| つむぎ | AI 相談員。導入の語り手 | 列にはいない |
| 陽向 | 芽衣に絵文字だらけの LINE を送り、既読のまま返ってこないことを気にしている生徒 | 列 0。最初から見える |
| 芽衣 | 返信を考えているうちに授業が始まり、既読のままになってしまった生徒 | 列 1。最初から見える |
| 保健室の先生 | 昼の陽向と、放課後の芽衣を見ていた大人。口調は丁寧 | 列 2。最初から見える。画面の列名は「保健室の先生」 |
| 莉子 | 放課後に芽衣と立ち話をし、夜に陽向の連絡を受け、翌日芽衣へそれとなく伝えた生徒 | 列 3。拡張するまで列ごと隠れる |

呼称はコードどおりです。陽向と芽衣は下の名前、先生は「保健室の先生」、莉子は「莉子」。先生の証言の中では「陽向さん」「芽衣さん」「莉子さん」です。読み仮名はコードにありません。

口調の目安:

- 陽向・芽衣は、ためらいのあるくだけた一人称（「……」「ちゃった」「気まずい」）。
- 先生は、観察を丁寧語で話す。
- 莉子は、丁寧だけれど硬い演説にはしない一人称。
- 「わかったこと」「さらにわかったこと」「分岐の結末」は、誰かのセリフではなく静かな地の文。

## グリッド

証言者が横、時間が縦です。左端の細い列（48px）が時間の見出し、上の行が人物の見出しです。

人物と時間は、最初から 4 人と 3 枠ぶん定義されています。拡張前は先頭だけを描きます。

- 人物 `witnesses`: 陽向、芽衣、保健室の先生、莉子
- 時間 `times`: 昼休み、放課後、その夜
- 拡張前: 人物は先頭 3 人、時間は先頭 2 枠
- 拡張後: 4 人、3 枠のすべて

マスのキーは `"行-列"` です。行も列も 0 始まりです。例: `"0-1"` は昼休み × 芽衣、`"1-0"` は放課後 × 陽向、`"2-3"` はその夜 × 莉子。

拡張前（3 列 × 2 行）:

|  | 陽向 | 芽衣 | 保健室の先生 |
| --- | --- | --- | --- |
| 昼休み | id 1 | id 2 | id 3 |
| 放課後 | 記録なし | id 4・分岐点 | id 5・キーワード「莉子」 |

拡張後（4 列 × 3 行）:

|  | 陽向 | 芽衣 | 保健室の先生 | 莉子 |
| --- | --- | --- | --- | --- |
| 昼休み | id 1 | id 2 | id 3 | 記録なし |
| 放課後 | 記録なし | id 4・分岐点 | id 5・キーワード「莉子」 | 記録なし |
| その夜 | id 6 | 記録なし | 記録なし | id 7 |

置けるマスは 7 つで、証言も 7 つです。記録なしを除けば、空いたマスが余ることはありません。すでに置いたカードは、リセットするまで剥がせません。

## 証言

`testimonies` の各要素が 1 枚です。`row` が時間、`col` が人物、`group` が `base`（最初から手札にある）か `expansion`（拡張後だけ手札に出る）です。`pivot: true` は分岐点、`keyword` はその文字列をタップすると拡張が開く印です。該当するのはそれぞれ 1 枚だけです。

### id 1 · 陽向 · 昼休み · base

- キー: `0-0`
- 分岐点: なし
- キーワード: なし
- 本文: 今日、芽衣に絵文字だらけのLINE送ったら既読スルーされてて……ちょっと引かれたかもって思っちゃいました。

陽向本人の発言です。相手は芽衣ですが、マスは陽向です。

### id 2 · 芽衣 · 昼休み · base

- キー: `0-1`
- 分岐点: なし
- キーワード: なし
- 本文: 既読つけたまま返信考えてたら、次の授業始まっちゃって。既読無視したみたいになってて気まずいです……

芽衣本人の発言です。無視したつもりはなく、返信を考えているうちに授業が始まった、という内容です。

### id 3 · 保健室の先生 · 昼休み · base

- キー: `0-2`
- 分岐点: なし
- キーワード: なし
- 本文: 陽向さん、いつも通りお昼には来てくれたんですけど、心なしかスマホをちらちら気にしてる様子でした。

先生が陽向を見ていた記録です。陽向の列ではありません。

### id 4 · 芽衣 · 放課後 · base · 分岐点

- キー: `1-1`
- 分岐点: あり（`pivot: true`）
- キーワード: なし
- 本文: 放課後、教室で陽向を見かけたけど、話しかけるタイミングを逃しちゃって、そのまま帰っちゃいました。

このマスに置くと、マスの右上に「分岐点」という小さな札が付きます。札は CSS の `::after` で、本文とは別です。差し替えの操作そのものは、基本の 5 枚がすべて置かれるまで出ません。差し替え後の文章は証言配列には入っておらず、別の `pivotRevised` にだけあります。内容は「分岐点」の節に書きました。

### id 5 · 保健室の先生 · 放課後 · base · キーワード

- キー: `1-2`
- 分岐点: なし
- キーワード: `莉子`
- 本文: 芽衣さんが放課後、莉子さんと少し立ち話をしてから保健室の前まで来て中を覗いて、そのまま帰っていくのを見ました。声をかければよかったと、今は少し後悔しています。

正しく置いたときだけ、本文中の最初の「莉子」が波線の下線つきでタップできます。手札のあいだは普通の文字です。「さん」は下線の外です。

### id 6 · 陽向 · その夜 · expansion

- キー: `2-0`
- 分岐点: なし
- キーワード: なし
- 本文: 夜、莉子に『既読無視されたと思って、なんか落ち込んじゃった』ってLINEしちゃいました。柄にもなく愚痴っちゃったかも。

拡張するまで手札に出ません。莉子へ送った話ですが、発言者は陽向です。莉子の列に置くと誤配置になります。

### id 7 · 莉子 · その夜 · expansion

- キー: `2-3`
- 分岐点: なし
- キーワード: なし
- 本文: 陽向から夜に連絡があって、話を聞いてました。次の日、それとなく芽衣に『既読、気にしてたみたいだよ』って伝えておきました。

拡張するまで手札に出ません。夜に陽向の話を聞き、翌日芽衣へ伝えた、という莉子の発言です。

`group` が `base` でも `expansion` でもない証言を足すと、拡張後の手札には出ますが、どちらの勝ち条件にも数えられません。基本の勝ちは `group === 'base'` の全枚、拡張の勝ちは `group === 'expansion'` の全枚です。

## 記録なし

`isEmptyCell` が真のマスは、最初から「（記録なし）」です。点線ではなく実線、透明度 0.4、クリックしても何も起きません。手札も対応するカードはありません。

| キー | マス | いつ描かれるか | コード上の理由 |
| --- | --- | --- | --- |
| `1-0` | 放課後 × 陽向 | 最初から | コメントは「陽向・放課後は先に帰っていた」 |
| `0-3` | 昼休み × 莉子 | 拡張後 | コメントは「莉子登場前」 |
| `1-3` | 放課後 × 莉子 | 拡張後 | 同じコメントにまとめて入っている |
| `2-1` | その夜 × 芽衣 | 拡張後 | コメントは「その夜に証言がない人」 |
| `2-2` | その夜 × 保健室の先生 | 拡張後 | 同上 |

コメントと本文は、完全には揃っていません。芽衣の id 4 は、放課後の教室で陽向を見ています。先生の id 5 は、放課後に莉子と芽衣が話したのを見ています。プレイヤーには理由の文は出ず、マスには「（記録なし）」とだけ書きます。揺れは [KNOWN_ISSUES.md](KNOWN_ISSUES.md) に観察として残しています。

## 物語として読めること

正しい配置だけを追うと、流れは次のとおりです。ゲームはこの文章を途中で組み立てず、全部置いたときに用意された解決文を出します。

1. 昼、陽向は芽衣へ絵文字の多い LINE を送り、既読のままなので引かれたのかもしれないと思う。
2. 芽衣は返信を考えているうちに授業が始まり、既読無視に見えて気まずい。
3. 先生は、昼の保健室の陽向がスマホを気にしているのに気づいている。
4. 放課後、芽衣は教室で陽向を見るが、声をかけられず帰ってしまう。ここが分岐点で、後から「声をかけた」記憶に差し替えられる。
5. 先生は、芽衣が莉子と立ち話をしたあと保健室の前まで来て中を覗き、帰っていくのを見る。声をかけなかったことを後悔する。この「莉子」が拡張の入口。
6. 夜、陽向は莉子へ、既読を気にして落ち込んだと送ってしまう。
7. 莉子はそれを聞き、翌日、芽衣へ「既読を気にしていたようだ」とそれとなく伝える。

基本の解決は「誰も悪くないすれ違いで、翌日も少しぎこちない」。差し替え後は「その場で誤解が解け、翌日はいつもの昼」。拡張の解決は「二人は直接話さなくても、莉子を介して気まずさが溶けかけていた」。この三つの文は、同時に画面へ出せます。両立しない部分は観察メモ側に書いてあります。

## カードの選択と配置

手札の見出しは「つむぎと先生が覚えている言葉（タップして選択 → マス目に配置）」です。

手札に出るカードは、まだ正しいマスへ置いていない証言のうち、次のどちらかです。

- `group` が `base`
- すでに拡張している（このときは `base` 以外も出る）

並びは、残っている id の組み合わせごとに一度だけシャッフルします。組み合わせを表すキーは、残っている id を昇順にしてカンマでつないだ文字列です。同じ組み合わせのあいだ（カードを選んだだけ、選ばれた印が付いているだけ）は並びを維持します。1 枚置くか、拡張でカードが増えると組み合わせが変わるので、残りを並べ直します。拡張の直前には `poolOrder` を捨て、必ず並べ直します。

操作:

1. カードをタップすると選ばれる。もう一度タップすると選択が解ける。同時に選べるのは 1 枚。
2. 選ばれたカードは、左の太い線と枠が珊瑚色になり、背景が `#fdeeea`、外側に薄い赤の輪が付く。
3. 「空き」と書いてあるマスをタップすると、選択中のカードをそこに置こうとする。
4. カードの `row` と `col` がそのマスと一致すれば置く。選択は解け、表と手札を描き直し、基本の勝ちと拡張の勝ちをこの順で調べる。
5. 一致しなければ置かない。選択は残る。

記録なしのマスと、すでに埋まっているマスは、配置の対象ではありません。キーワード付きで埋まったマスだけ、後述のタップを受けます。

何も選んでいないときに空きマスをタップしても、無反応です。

## 誤配置

違うマスだったとき、そのマスにだけ次が付きます。

- `wrong`: 枠が `#cf6e78`、背景が珊瑚色の 25% 透明。1 秒後に外れる。
- `shake`: 左右へ 5px 揺れるアニメーション。0.35 秒後に外れる。

説明の文は出ません。カードは選ばれたままなので、別のマスを続けて試せます。同じマスを 1 秒以内に何度も外すと、それぞれの解除タイマーが独立しているため、後の赤枠が先のタイマーに消されることがあります。

## 基本の勝ち

`group` が `base` の 5 枚（id 1 から 5）が、それぞれのマスに入ったときです。記録なしは条件に入りません。拡張の 2 枚は不要です。拡張より先でも、後でも構いません。

初めて揃ったとき（解決欄がまだ隠れたままのとき）だけ、次を行います。

- 「わかったこと」を表示する。
- 本文: ただの既読スルーの気まずさが、お互いの思い込みで少しずつ大きくなっていた。誰も悪くない、ただのタイミングのすれ違い。次の日も、二人は少し気まずいまま保健室で過ごしている。
- 分岐の欄を開き、初期状態として「元の記憶」側の結末を出す。

この本文は、あとから分岐を切り替えても書き換わりません。もう一度この処理が走らないのは、解決欄が隠れていないあいだは条件を満たさないためです。リセットすると隠れるので、もう一度 5 枚置くと再び出ます。

## 分岐点

基本の勝ちのあと、解決欄の下に「もしも、ここが違ったら」が出ます。説明は「分岐点の言葉を、別の行動の記憶に差し替えてみる。」です。

選択肢は二つです。

| キー | ラベル | マスに出る本文 | 結末の札 | 結末 |
| --- | --- | --- | --- | --- |
| `original` | 芽衣 / 放課後（元の記憶） | id 4 の原文 | 現在（元のまま）（珊瑚色、`bad`） | ただの既読スルーの気まずさが積み重なったまま、次の日も二人はどこかぎこちない。 |
| `revised` | 芽衣 / 放課後（差し替え後） | 下の改訂文 | 現在（改訂後）（セージ色、`good`） | 二人はその場で笑い合って誤解が解け、次の日からまたいつも通り保健室でお昼を食べている。 |

改訂文（`pivotRevised.text`）:

> 放課後、保健室の前で陽向を見かけたので、思い切って『さっきのLINE、既読無視したみたいでごめん』って声をかけました。

挙動:

- 最初は元の記憶が選ばれています。`revisedActive` は `false` です。
- 差し替え後を選ぶと `revisedActive` が `true` になり、表の芽衣 × 放課後だけが改訂文になります。「分岐点」の札は残ります。
- 元の記憶に戻すと、マスも結末も元に戻ります。
- 置いてあるオブジェクト自体は書き換えません。描画のとき、その証言が分岐点で、かつ差し替え中なら、原文の代わりに改訂文を出します。
- 手札には、この時点で id 4 は残っていません。改訂文が手札に混ざることもありません。
- 他のマス、先生の放課後の証言、「わかったこと」の本文は変わりません。
- 拡張の勝ち条件にも影響しません。

## キーワード「莉子」

id 5 を正しいマスへ置いたあと、本文の「莉子」だけが `.keyword` になります。見た目は、珊瑚色の太字と、同じ色の波線です。カーソルは指先です。

その文字をタップすると `triggerExpansion` が走ります。文字の外をタップしても拡張しません。画面のどこにも「タップできる」「続きがある」とは書きません。波線が唯一の目印です。

拡張で起きること:

- `expanded` が `true` になる。二度目以降のタップは、すぐ戻って何もしない。
- 手札の並びを捨てて、表と手札を描き直す。
- 列に莉子、行に「その夜」が増える。記録なしのマスも増える。
- まだ置いていない拡張の証言（id 6 と id 7。片方が既に置いてあることは、拡張前には手札に出ないので通常は起きない）が手札に加わる。
- 表の下に通知が出る。本文: 新しい記録が見つかった → 「その夜」の時間軸と、莉子の証言が追加されました。

拡張は、基本の 5 枚が揃う前でもできます。id 5 さえ置いて、その「莉子」をタップすれば足ります。通知はリセットするまで残ります。

## 拡張の勝ち

拡張済みで、`group` が `expansion` のすべて（id 6 と id 7）がそれぞれのマスにあるときです。基本の 5 枚は不要です。

揃うと「さらにわかったこと — その夜」が出ます。本文:

> 実は、芽衣の既読無視を陽向はずっと気にしていて、その夜莉子に思わずこぼしていた。莉子は次の日、それとなく芽衣に陽向の様子を伝えていた——放課後のあの気まずさは、二人が直接言葉を交わさなくても、少しずつ溶けていくところだった。

この欄は、分岐の下に出ます。一度出たら、リセットするまで残ります。

## リセット

ボタンのラベルは「はじめから」です。押すと次の状態に戻し、表と手札を描き直します。確認はありません。

- 置いたカード、選択、差し替え、拡張、手札の並びをすべて捨てる。
- 「わかったこと」、分岐、拡張の通知、「さらにわかったこと」を隠す。

リロードでも同じ初期状態に戻ります。進行は保存しません。

## 画面に出る欄の順

上から次の順です。隠れた欄は隙間を作りません。

1. 顔のイラスト、肩書き、見出し、導入
2. グリッド
3. 拡張の通知
4. 手札の見出しとカード
5. 「はじめから」
6. 「わかったこと」
7. 分岐（選択肢と、いまの結末）
8. 「さらにわかったこと — その夜」

| `--muted` | `#9c9284` | 導入、空マス、「記録なし」以外の補助文 |

背景は上から下への直線グラデーションです。語義としては、セージが整理と基本の解決、コーラルが感情・分岐・キーワード・拡張です。

変数にない直接の色: 選択中カードの背景 `#fdeeea`、顔の円の塗りも `#fdeeea`、分岐ラベルの小さい文字 `#b98088`、分岐点の札の文字は白。

### 文字

Google Fonts を読みます。

`Shippori Mincho` の 400 / 600 / 800 と、`M PLUS Rounded 1c` の 400 / 500 / 700。URL には `display=swap` が付いています。

- 明朝（Shippori Mincho）: ページ全体、見出し、証言、解決の本文。見出しだけ太さ 800。
- 丸ゴシック（M PLUS Rounded 1c）: 肩書き、導入、表の見出し、通知、手札の見出し、ボタン、各欄の小見出し、分岐の説明。ラベル類は太さ 700。導入や通知のように太さを指定しない箇所は 400。

CSS から太さ 600 と 500 は参照していません。読み込み URL には含まれています。

### 480px の紙面

- `body`: 余白は上 22px、左右 14px、下 60px。横スクロールは隠す。
- `.wrap`: 最大幅 480px、中央寄せ。
- 表: 先頭列 48px、残りを人物数で等分。マスの最小高さ 78px、角丸 10px、マス同士の隙間 6px。
- 空マスは中央寄せの点線。埋まったマスは左寄せ、上寄せ、セージの実線、薄い影。
- カードは角丸 10px、左に 5px の色帯。選択中は珊瑚色。
- ボタンは白地にセージの枠、角丸 20px。押しているあいだ背景がセージ、文字が白。
- 顔は 46×46 のインライン SVG。薄い珊瑚の円に、二つの点と弧の口。画像ファイルはありません。

拡張後は人物が 4 人になるので、幅 480px 以下では 1 マスが狭くなります。列の定義は `48px repeat(4, 1fr)` で、列のあいだは 6px です。紙面の最大幅は 480px、ページの左右余白は 14px なので、スマホでは見出しを除いた残りを 4 列と隙間で分けます。

## データ

すべてそのページの JavaScript の変数です。モジュールやクラスはありません。

### 固定データ

- `witnesses`: 長さ 4 の文字列配列。添字が列。
- `times`: 長さ 3 の文字列配列。添字が行。
- `testimonies`: 上の 7 件。オブジェクトは `{ id, row, col, group, text, pivot?, keyword? }`。
- `pivotOriginal`: `pivot` を持つ証言への参照。id 4 そのものです。コピーではありません。
- `pivotRevised`: `{ text }` だけを持つオブジェクト。id も行も列もありません。

### プレイ中の状態

- `placed`: オブジェクト。キー `"行-列"` の値は、置かれた証言オブジェクトへの参照。初期値は `{}`。
- `selectedId`: 選んでいる証言の `id`。未選択は `null`。
- `revisedActive`: 差し替え後を表示しているか。初期値 `false`。
- `expanded`: 拡張済みか。初期値 `false`。
- `poolOrder`: `null`、または `{ idsKey, order }`。`order` はシャッフルした id の配列。

DOM への参照は起動時に一度だけ取ります。`grid`、`pool`、`expansionNotice`、`resolution`、`resolutionText`、`revisionSection`、`revOptions`、`outcomeTag`、`outcomeText`、`expansionResolution`、`expansionResolutionText`。表示の切り替えは、これらの `hidden` クラスで行います。

## 関数

呼び合う関係だけ書くと、起動時は `buildGrid` と `buildPool` です。空きマスのクリックは `onCellClick`、そこから二つの勝ち判定です。キーワードは `triggerExpansion`。基本の勝ちは `buildRevision` と `updateOutcome`。リセットは状態を捨てて二つの build を呼び直します。

### `shuffled(arr)`

配列をコピーし、末尾からフィッシャー–イェーツで並べ替えて返します。元の配列は変えません。乱数に種はありません。

### `currentWitnesses()` / `currentTimes()`

拡張前は `slice(0, 3)` と `slice(0, 2)`、拡張後は配列全体です。表の列数・行数はここから決まります。

### `isEmptyCell(key)`

上の「記録なし」の表が真なら `true`。拡張前は、拡張後専用のキーを調べても、そのマス自体を描かないので画面には出ません。`1-0` だけは常に記録なしです。

### `buildGrid()`

表を空にして描き直します。列の並びは `48px` に人物数ぶんの `1fr` です。

各マス:

- 記録なしなら `disabled` と「（記録なし）」。クリックは付けない。
- 置いてあれば `filled`。分岐点で差し替え中なら改訂文、そうでなければ原文。キーワードがあれば、その語を `span.keyword` に置き換えて `innerHTML` で入れ、クリックで拡張を試す。なければ `textContent`。分岐点なら `pivot` クラスも付ける。
- どちらでもなければ「空き」。クリックで `onCellClick`。

キーワードの置換は、文字列の最初の 1 回だけです。

### `buildPool()`

条件に合う未配置の証言を集め、組み合わせが変わったときだけ `shuffled` で順を作り、カードを描きます。本文は `textContent` なので、手札側に下線は出ません。クリックで選択をトグルし、手札だけ描き直します。表は描き直しません。

### `onCellClick(row, col, cellEl)`

未選択なら戻ります。選択中の証言の行と列が一致すれば `placed` に入れ、選択を消し、表と手札を描き、`checkBaseWin` のあと `checkExpansionWin` を呼びます。不一致なら `wrong` と `shake` を付け、350ms で揺れを、1000ms で赤枠を外します。

### `triggerExpansion()`

すでに拡張済みなら何もしません。そうでなければ拡張フラグを立て、手札順を捨て、表と手札を描き、通知の `hidden` を外します。

### `checkBaseWin()`

基本の証言がすべて `placed` にあり、解決欄がまだ隠れていれば、解決文を入れ、分岐を組み立て、両方を表示し、結末を元の記憶側で更新します。

### `checkExpansionWin()`

未拡張なら戻ります。拡張の証言がすべて置かれていれば、その夜の解決文を表示します。

### `buildRevision()`

二つの選択肢を描き直します。いまの `revisedActive` と一致する側に `active` を付けます。クリックするとフラグを更新し、表、選択肢、結末を描き直します。

### `updateOutcome()`

`revisedActive` が真なら「現在（改訂後）」と和解の文、偽なら「現在（元のまま）」とぎこちなさの文です。札のクラスは `outcome-tag good` または `outcome-tag bad` で、色だけが変わります。

### リセットのクリック

状態を初期値に戻し、四つの欄に `hidden` を付け、表と手札を描き直します。解決文の文字列を空にはしませんが、次に勝ったときに上書きします。

## 初期化

スクリプトの末尾で `buildGrid()` と `buildPool()` を一度ずつ呼びます。この時点の手札は、基本の 5 枚をシャッフルしたものです。表は空マス 5 つと記録なし 1 つです。

## テスト版だけにあるもの

`test/index.html` は、`<body>` の直後に `TEST-BADGE-START` から `TEST-BADGE-END` までのブロックが挿入されている以外、`index.html` と同一です。ブロックの中身は、右上に固定した「テスト版」バッジのスタイルと要素だけです。`pointer-events: none` なので、下のゲームのクリックを奪いません。ゲームの状態や文章には触れていません。

本番へ戻す手順は [AGENTS.md](../AGENTS.md) にあります。

## このゲームにないもの

次は未実装であり、抜けではありません。足すときは仕様ごと変える必要があります。

- 進行の保存と復元
- スコア、制限時間、ヒントボタン、効果音
- 間違った配置でも進んでしまう別解
- 分岐や拡張に応じて他の証言を書き換える処理
- ビルド、フレームワーク、サーバ
